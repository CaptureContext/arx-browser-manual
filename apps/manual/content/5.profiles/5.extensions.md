Arx runs Chrome extensions. Each extension belongs to one profile and works in all of its spaces, so a work extension never sees your personal browsing.

Manage them in **Settings → Profiles → ‹profile› → Manage Extensions…** The sheet's bar has a **Close** button (:keys{combo="Esc"}) on the left and its actions as icons on the right. Hover an icon to see its name.

To get there from a window, choose **Window → Extensions**, type `arx://extensions` in the address bar, or click **Manage** in the [site menu](/pages/site-menu#extensions), which also lists the profile's enabled extensions. In Settings, you can also type `extensions` in the search field.

## An extension's settings

Arx shows an extension's settings in a few places:

- **In the site menu**, click an extension to open its popup, where many extensions keep their settings. Right-click it and choose **Options** to go straight to its options page, if it has one, or **Manage Extensions** to open the Extensions sheet on it.
- **In the Extensions sheet**, select the extension and click **Options**. After you install an extension, the sheet already has it selected.
- **In Settings**, search for `extensions`, `add-ons` or `options`. Arx opens the selected profile's Extensions sheet.

Some extensions have no options page and keep their settings in the popup they show when you click their icon. Click the extension in the [site menu](/pages/site-menu#extensions) to open that popup on the page you're on.

## An extension's popup

When you click an extension in the [site menu](/pages/site-menu#extensions), or press its shortcut, its popup opens in a small window of its own, just under where you clicked, with the keyboard in it. The window has the extension's icon, its name and a **Close** button at the top, and it's as big as the popup asks for: when the popup changes size, so does the window.

- **It stays open** while you work in the page behind it, choose a file, sign in or switch to another app, and it stays above the window you opened it from. It moves with that window, and steps aside while the window shows its command bar or a sheet.
- **Drag it by its top** to move it out of the way.
- **Close** it with its **Close** button, :keys{combo="⌘ W"} or Escape. An extension can close its popup itself, too.
- **Click the extension again** while its popup is open and the open one comes forward. Each extension has one popup per page.

A popup belongs to the page you opened it on: it closes when that page goes to another site, closes, or you switch to another tab. It's in that page's profile, and in a private window it's in that window.

## Windows an extension opens

Some extensions open a window of their own, such as 1Password's pop-out and unlock window. Arx opens it in a [Little Arx](/tabs/little-arx) window in the extension's profile, in front, so you can type in it straight away. It closes when the extension closes it, and you can close it yourself like any Little Arx.

The window has Little Arx's size and place, not the size the extension asks for.

An extension that opens one of its own pages in a new tab, such as 1Password's welcome and sign-in page, gets the same Little Arx. A page on the web that an extension opens in a new tab doesn't open yet.

## What you can do

- **Enable**, **Disable** and **Remove** an extension. Removing asks first. The [site menu](/pages/site-menu#extensions) has **Turn Off** and **Remove…** too.
- **Allow in private windows** lets an extension run in private windows. See [below](#private-windows).
- See its **permissions**, and **Open Options** when it has an options page.
- **Refresh** (the arrow at the end of the bar) reloads the list.
- **Chrome Web Store** (the bag) opens the store in this profile. See [below](#chrome-web-store).
- **Check for Updates** (the circling arrows) looks for newer versions of this profile's Chrome Web Store extensions. See [Updates](#updates).
- **Install Package…** (the box) installs a signed `.crx` file, and **Update from Package…** updates one. A review sheet shows the package's hash and permissions first.
- With [developer mode](/developers/developer-mode) on, **Load Unpacked…** (the folder with a plus) loads a folder you're working on.

## Chrome Web Store

::preview{scene="extensions"}

1. Open the store in the profile you want the extension in. Any of these works:
   - Click **Chrome Web Store** in the Extensions sheet's bar. When the profile has no extensions yet, the empty list has the same button.
   - Press :keys{combo="⌘ K"} and type `web store` or `get extensions`, then choose **Chrome Web Store**.
   - Choose **Window → Chrome Web Store**.
   - Click **+** in the [site menu](/pages/site-menu#extensions)'s extensions row.

   The store opens in a new [Little Arx](/tabs/little-arx) of that profile, in front. The site menu's **+** and **Add Extension** work in a Little Arx's site menu too.
2. On an extension's page, click **Add to Arx**. That's the store's "Add to Chrome" button.
3. Arx downloads the extension from the store and checks that Google signed it. Then the Extensions sheet opens with the same review as for a package: the extension's name, version, its publisher when the extension names one, the package's SHA-256 hash, the permissions it asks for and their warnings.
4. Click **Install**, or **Cancel** to leave everything as it was. The store shows the result, and the sheet selects the new extension.

The review comes up even when Settings is closed or shows another profile: Arx switches Settings to the page's profile first.

You don't need to sign in to Google, or have a Google account, to install from the store.

The extension goes into the profile whose page you clicked **Add to Arx** in. Other profiles don't get it; add it there separately.

To remove a store extension, use **Remove** in the Extensions sheet or the [site menu](/pages/site-menu#extensions), or the store's own **Remove from Arx** button. The store's button asks first in a sheet on the window, then removes the extension from that profile.

### When an assistant asks to install one

An [assistant](/assistants/tools#browser_settings) you've granted a whole profile can ask to install a Chrome Web Store extension in it. Arx never installs it on the assistant's say-so: it opens that profile's Extensions sheet with the same review as **Add to Arx**, and a line at the top names the assistant that asked. Click **Install** to add it, or **Cancel** to leave everything as it was. Closing the sheet counts as **Cancel**.

The review comes up every time, whatever approval policy you gave the assistant, and never while an assistant runs unattended. If the profile already has the extension, the sheet shows it with nothing to review, and the assistant is told so.

## Updates

Extensions you added from the Chrome Web Store stay up to date:

- Arx checks the store for newer versions a few minutes after it starts and then every few hours, for each profile that has a window open.
- An update that asks for nothing new installs on its own, as in Chrome.
- An update that asks for more permissions waits for you. Its extension says **Update needs review**: on its row in the Extensions sheet, on the profile's Extensions entry in Settings, and as an orange dot on its tile in the site menu.
- Click the mark beside the row, or **Review Update…** in the extension's details or in its tile's menu in the site menu. The review sheet shows the new version, the package's hash and every permission it asks for. **Install** updates it; **Cancel** keeps the version you have, and Arx doesn't ask about that version again. A newer one gets its own mark.
- The mark also goes when the extension updates another way, for example with **Check for Updates**, or when you remove it.

Turning off **Extension update review** in **Settings → Advanced → Feature Flags** (the `ARX_EXTENSION_UPDATE_REVIEW` feature flag) and relaunching Arx removes the marks: such an update then waits silently for **Check for Updates**.

**Check for Updates** checks the profile's store extensions right away, shows the review of any update that asks for more permissions, and then says how many it updated. Each check sends Google the IDs of the extensions it asks about, as adding one from the store does. Every profile is checked on its own, and an update reaches only the profile the extension is in.

Extensions installed from a package update with **Update from Package…** instead.

## Right-click menus

Extensions that add items to the right-click menu, such as password managers, translators or "save to" extensions, show them in Arx's menus for the page, a link, an image, a video or audio, selected text and text fields. They come after Arx's own items and before **Inspect Element**: an extension with one item shows it with the extension's icon, one with several shows a submenu named after the extension. Choosing an item hands the extension what you right-clicked, such as the link or the selected text.

## Password managers and other desktop apps

Some extensions talk to an app on your Mac through native messaging: 1Password, Bitwarden and KeePassXC connect to their desktop apps this way to unlock and fill. Arx finds the connection files these apps install for Chrome and Chromium, so turn on the browser integration in the app's settings as you would for Chrome.

Arx looks in this order, first match wins:

1. `~/Library/Application Support/dev.capturecontext.arx/NativeMessagingHosts`, for an app that knows Arx, or a file you put there yourself
2. `~/Library/Application Support/Google/Chrome/NativeMessagingHosts`
3. `~/Library/Application Support/Chromium/NativeMessagingHosts`
4. `/Library/Application Support/dev.capturecontext.arx/NativeMessagingHosts`, `/Library/Application Support/Chromium/NativeMessagingHosts` and `/Library/Google/Chrome/NativeMessagingHosts`, for every user of the Mac

Each file names the extensions that may connect, so only those can. Some apps also check which browser is asking and only answer browsers they know. If the extension says it can't reach the app, look for a list of browsers in the app's settings.

### 1Password

1Password's app checks the browser's code signature and answers only browsers it supports or that you added yourself. Arx isn't on its list, so add it in 1Password 8: open **Settings › Browser**, choose **Add Browser** and pick Arx in your Applications folder.

Until the app answers, use the extension on its own: click 1Password in the [site menu](/pages/site-menu#extensions). Until you sign in, it opens its welcome page in a Little Arx, where you sign in to your 1Password account.

## Private windows

A [private window](/tabs/private-windows) belongs to the profile you opened it from, and only that profile's extensions with **Allow in private windows** on run in it. The switch is in each extension's row in the Extensions sheet, and in its menu in the [site menu](/pages/site-menu#extensions) (**Allow in Private Windows**). It's off for every extension until you turn it on, because an extension allowed there can see and change the pages you open privately.

An extension allowed in private windows filters and changes their pages and can talk to its desktop app there. Its button is in a private window's [site menu](/pages/site-menu#private-windows), its popup opens there, its right-click items show on private pages, and it sees private windows' tabs, as in Chrome.

A few extensions keep a separate copy of themselves for private windows that starts only when needed. They can't run in private windows and don't have the switch. A private window's site menu names them.

[Content blocking](/pages/content-blocking) has no switch: it always works in private windows.
